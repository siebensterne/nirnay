Expand description

One instrument’s assigned tick for one term interval.

NSE assigns tick sizes monthly, per instrument: the tick that applies for the whole month M is determined by the closing price at the end of month M-1 (NSE circular CMTR67133, effective 2025-04-15; monthly review thereafter). The assignment is therefore a record — reference closing price, the month it governs, the assigned tick, and the schedule revision that produced it — not a live lookup against the price at decision time. A venue whose master assigns a per-security tick directly (BSE New Tick Size) leaves the two monthly fields None.

Trading engines must use tick_paise verbatim for the term interval; recomputing from the order price would wrongly change the tick whenever the price crosses a band boundary mid-month.

Fields§

§tick_paise: i64

Assigned tick size, in paise.

§reference_close_paise: Option<i64>

Reference closing price (paise) that fixed the assignment; None for non-monthly assignments.

§reference_close_date: Option<Date>

Trading date of the reference close. For an NSE monthly assignment this is the last available close of the month immediately preceding effective_month; an arbitrary price cannot be assigned.

§reference_source: Option<String>

Identity of the dataset the reference close came from (e.g. nse-eod-close). Never empty for a monthly assignment.

§reference_sha256_hex: Option<String>

SHA-256 of the exact reference-close source bytes, so the price can be reproduced from the archive. 64 lowercase hex digits.

§effective_month: Option<Date>

First day of the month this assignment governs; None for non-monthly assignments.

§schedule_revision: String

Exchange tick-schedule revision the assignment was computed under, as {source_id}:{source_format_version}. Never empty.

§schedule_effective_from: Option<Date>

Date from which that schedule revision is in force.

§schedule_sha256_hex: Option<String>

SHA-256 of the exact schedule source bytes.

§calendar_revision: Option<String>

Exchange-calendar revision the assignment was determined under, as {source_id}:{source_format_version}. Required for a monthly assignment; None for a non-monthly assignment.

§calendar_sha256_hex: Option<String>

SHA-256 of the exact holiday-calendar source bytes whose sessions fixed the reference close date. Required for a monthly assignment; None for a non-monthly assignment.

impl TickAssignment

pub fn validate(&self) -> Result<(), Error>

Validate the assignment record and its price-source lineage.

A monthly assignment is only reproducible when it names the reference close date, the dataset, that dataset’s hash, the schedule revision, the schedule hash, the calendar revision and the calendar hash, and the effective month. The reference close must fall in the month immediately preceding the effective month — the NSE determination rule (previous month’s last available close) — so a close from the wrong month is rejected rather than silently applied.
