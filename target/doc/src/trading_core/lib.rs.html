2//! Trading domain and event contracts for the India platform.
3//!
4//! Derived from the internal Nirnay (`crates/nirnay-core/src/types.rs`,
5//! `model.rs`, `risk.rs`) at source snapshot
6//! `cc3a34c317a86a9984401efe90fa3f43d67a1787`.
7//!
8//! The port does **not** keep Nirnay's instrument identity,
9//! money, quantity or side types. Those are mapped onto the canonical
10//! `india-domain` instrument model and `market-types` side semantics:
11//!
12//! - [`InstrumentId`] is `india_domain::InstrumentId`: one canonical identity.
13//! - [`Paise`] is `india_domain::Paise`: exact integer cash.
14//! - [`Lots`] is `india_domain::Lots`: quantity is measured in lots.
15//! - [`Side`] is `market_types::Side`: Buy = 0, Sell = 1.
16//! - [`PricePaise`] is a validated positive price with explicit, lossless
17//!   conversions to and from canonical paise.
18//!
19//! Event identity is deterministic for a run ([`EventId::for_run`]) so the
20//! same simulated input produces the same journal bytes and hashes. A live
21//! caller supplies a distinct [`RunId`]; a replay supplies the recorded one.
